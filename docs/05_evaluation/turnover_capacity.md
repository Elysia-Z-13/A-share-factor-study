# turnover_capacity.md —— 换手、容量与 kill（E6）

> 最大换手 = 毛收益 ÷ 单位换手成本 ｜ 最小 edge = 成本 ÷ 持有期 ｜ 容量 = 参与率 × ADDV ÷ 换手 ｜ kill 部署前写死

## 一、换手（G3.2）

**标准口径**：单边换手 = ½ × Σ|目标权重 − 漂移权重|

| 项 | 2 因子 | 3 因子 |
|---|---|---|
| 期换手（单边） | 52.6% | 49.5% |
| 每年期数 | 4（季度） | 4 |
| **年换手** | **2.10 倍** | **1.98 倍** |
| 平均持有期 | 120 交易日 | 127 交易日 |

**⚠️ 与 E4 的口径差异（如实说明）**：

```
E4 用的是「集合口径」：0.5 × (|cur−prev|/|cur| + |prev−cur|/|prev|)
本步用「权重口径」：½ × Σ|Δw|

等权组合、全换手时两者等价
本例差异很小（因为每只权重都是 1/k）
→ 两口径一致，无需调整
```

## 二、最大可承受换手（G3.3）

**手册给两个版本**：

```
激进版：最大换手 = 年化毛超额 ÷ 每单位换手成本
保守版：最大换手 = Sharpe × 波动 ÷ 每笔成本（把风险算进去）
```

| 组 | 年化毛超额 | 往返成本 | **激进版上限** | **保守版上限** | 当前年换手 | 余量（激进/保守） |
|---|---|---|---|---|---|---|
| **2 因子** | +2.20% | 41.9bp | **5.25 倍/年** | 3.05 倍/年 | 2.10 倍 | **2.50× / 1.45×** |
| 3 因子 | +3.11% | 41.9bp | 7.42 倍/年 | 3.45 倍/年 | 1.98 倍 | 3.75× / 1.74× |

**判读**：
```
2 因子：当前年换手 2.10 倍
  激进版允许 5.25 倍 → 余量 2.50×
  保守版允许 3.05 倍 → 余量 1.45×
→ 两版都过，但保守版余量只有 1.45×，不宽裕
→ 含义：如果换手翻倍（比如改成月度调仓），成本就会吃掉大部分超额
```

## 三、最小所需 edge

**公式**：每日期望 edge > 往返成本 ÷ 平均持有天数

| 组 | 往返成本 | 平均持有 | **所需 edge** | **实际 edge** | 倍数 |
|---|---|---|---|---|---|
| 2 因子 | 41.9bp | 120 天 | 0.35bp/天 | **0.87bp/天** | **2.50×** |
| 3 因子 | 41.9bp | 127 天 | 0.33bp/天 | 1.23bp/天 | 3.75× |

**结论**：实际 edge 是所需 edge 的 **2.50 倍**，有安全边际。

## 四、容量（G3.4）—— 这是本步最重要的发现

**公式**：

```
日均交易能力 = 参与率上限 × ADDV
可承载规模 = 日均交易能力 × 建仓天数 ÷ 期换手
```

**参数**：参与率上限 5%（手册常用值）、建仓 5 天、期换手 52.6%

| 档位 | 假设 ADDV | 日均能力（5%） | 该档最大 AUM |
|---|---|---|---|
| 大盘 | 5 亿 | 2500 万 | **2.38 亿** |
| 中盘 | 2 亿 | 1000 万 | **0.95 亿** |
| 小盘 | 3000 万 | 150 万 | **0.14 亿** |

**整体容量（受最小档约束，三档各占 1/3）** = **0.43 亿**

### ⚠️ 目标资金严重超容量

```
目标 AUM = 1.0 亿
容量     = 0.43 亿
占比     = 234%

手册判定：目标资金 > 容量的 50% → 视为不可行
→ 234% >> 50% → **1 亿 AUM 不可行**
```

### 可行规模

```
可行 AUM = 容量 × 50% = 0.43 亿 × 0.5 = 2141 万
→ 约 2000 万
```

### 为什么容量比成本更早成为瓶颈

**手册的 A 股约定**（原文）：

> 小盘股多头端的价差常在 100–500bp，**容量往往比成本更早成为约束**。

**我们的实测正好印证**：

```
成本侧：break-even 49.5bp，真实 20.9bp，余量 2.36×  → 过
容量侧：目标 1 亿，容量 0.43 亿，占比 234%          → 不过

→ 成本不是瓶颈，容量才是
→ 这与手册的 A 股约定完全一致
```

### 三条放大的路径

| 路径 | 做法 | 容量放大 | 代价 |
|---|---|---|---|
| **延长建仓期** | 5 天 → 20 天 | **4×** → 1.7 亿 | 滑点上升、alpha 损耗增加 |
| **剔除小盘档** | 只买大中盘 | **约 9×** → 3.9 亿 | 丢掉小盘 alpha（而我们的因子在小盘更强） |
| 提高参与率上限 | 5% → 10% | 2× → 0.86 亿 | 冲击成本非线性上升 |

**⚠️ 一个自我矛盾要指出**：

```
E5 的成本是按 AUM=1 亿 算的，而 E6 说 1 亿超容量
→ 严格说不自洽

但影响小：我们的成本由「价差」主导，不是「参与率」主导
  三档参与率 0.01%~0.24%，即使 AUM 降到 2000 万也只降到 0.002%~0.048%
  → 仍然落在价差模型档，成本几乎不变
→ 所以 E5 的 20.9bp 在可行规模下仍然有效
```

## 五、alpha-to-go（快衰减信号的隐藏成本）

**手册的问题**：信号会衰减，建仓需要时间 → 建仓完成时 alpha 已消耗大半。

**规则**：信号半衰期 < 建仓所需时间 → 不可行。

| 项 | 值 |
|---|---|
| 信号半衰期 | 约 63 交易日（约 1 个季度） |
| 建仓时间 | 5 天 |
| 比值 | **7.9%** |
| **alpha 保留** | **96.0%** |

**为什么我们的 alpha-to-go 损耗很小**：
```
因子是财报数据，季频更新
→ 信息衰减慢（半衰期约 1 季度 = 63 交易日）
→ 建仓只要 5 天
→ 比值 7.9%，损耗可忽略

对比高频 alpha：半衰期 秒~分钟，建仓 分钟级
→ 比值接近 100%，alpha 在建仓完成前就没了
```

**半衰期的估计依据**：E1 的 timing placebo 显示 `dgm_q` 的 IC 从 k0 的 +0.0279 降到 k1 的 +0.0115（约 41%），
即一个报告期后衰减约一半 → 半衰期约 1 期 = 63 交易日。

## 六、kill 判据（G3.5，部署前写死）

| # | 名称 | 触发规则 | 动作 | 优先级 |
|---|---|---|---|---|
| K1 | **成本吃光超额** | 滚动 12 个月净超额 ≤ 0，且非成本模型错 | `stop` | block |
| K2 | **容量不足** | 目标资金 > 容量 | `reduce_size` | block |
| K3 | **符号翻转** | 3 个 regime 切片中 ≥2 个滚动 IC 与全样本反号 | `stop` | block |
| K4 | **回撤失控** | 回撤 > 回测 MDD 的 100%（即 −52.4%） | `stop` | block |
| K5 | **信号衰减** | 滚动 IC 连续 6 个月为负 | `stop` | block |

### 为什么必须部署前写

```
部署后的你，和部署前的你，是两个不同的人

部署前：客观，能算清「净超额连续12个月≤0就该停」
部署后：已投入时间和钱，会找理由
        「可能是成本模型错了」
        「可能是市场特殊」
        「再等一个季度看看」
→ 沉没成本谬误 + 处置效应

所以写进配置文件，到点自动停，没有人为判断空间
```

### 五条 kill 的当前状态（部署前基线）

| # | 当前是否触发 | 依据 |
|---|---|---|
| K1 成本吃光超额 | ❌ 未触发 | 净超额 +1.26%/年 > 0 |
| **K2 容量不足** | **⚠️ 已触发（1 亿 AUM）** | **占比 234% > 100%** |
| K3 符号翻转 | ⚠️ 部分触发 | E1 显示 `gm` 在 2022-2024 符号翻转；`dgm_q` 未翻转 |
| K4 回撤失控 | ❌ 未触发 | 回测 MDD −52.4%，是基线 |
| K5 信号衰减 | ⚠️ 关注中 | 2021-2024 净超额趋零（+0.2/−0.1/+0.1/−0.0） |

**⚠️ K2 已经触发**：如果按 1 亿 AUM 部署，第一件事就是违反自己的 kill 判据。
**部署规模必须降到 2000 万以下。**

## 七、结论

| 项 | 2 因子 | 3 因子 | 判定 |
|---|---|---|---|
| 年换手 | 2.10 倍 | 1.98 倍 | ✅ 可承受 |
| 最大可承受（激进） | 5.25 倍 | 7.42 倍 | ✅ 余量 2.50× |
| 最大可承受（保守） | 3.05 倍 | 3.45 倍 | ✅ 余量 1.45× |
| 最小 edge | 0.35bp/天 | 0.33bp/天 | ✅ 实际 2.50× |
| **容量** | **0.43 亿** | 0.45 亿 | **❌ 目标 1 亿超容量** |
| alpha-to-go 保留 | 96% | 96% | ✅ |
| kill 判据 | 5 条 | 5 条 | ✅ 已写死 |

### 三条核心结论

```
① 换手不是瓶颈：年换手 2.10 倍，上限 5.25 倍，余量 2.50×
② edge 有安全边际：实际是所需的 2.50 倍
③ **容量是硬约束：只有 0.43 亿，目标 1 亿超 2.3 倍**
   → 这是本项目第一个「不过」的量化约束
   → 手册的 A 股约定被证实：容量比成本更早成为瓶颈
```

## 八、已知局限

1. **ADDV 是假设值**（5亿/2亿/3000万），不是逐股实测。我们有成交额数据但未逐股匹配档位
2. **参与率上限取 5%**（手册常用值），未做敏感性（3%/5%/10%）
3. **建仓天数取 5 天**，未论证；若取 1 天容量降 5 倍
4. **容量公式忽略了「卖出也同样受限」**——实际上调仓是买卖双向，约束更强
5. **未做拥挤度分析**（手册第三层成本：拥挤度、机会成本）
6. **半衰期是从 timing placebo 粗估的**（k0→k1 衰减 41%），未做精细拟合
