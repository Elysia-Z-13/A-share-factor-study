## 一、为什么需要这张表

### 1.1 一个真实的发现过程

在 E3 做「跨特征集稳定」时，需要引用「全市场组 3 因子等权合成」的 IC。结果发现三份文档里有三个不同的数：

| 文档 | 报告的组合 IC | 出问题的环节 |
|---|---|---|
| `model_choice.md`（M-S） | **+0.0402** | 折内 rank（跨 14 期混合排名） |
| `signal_eval.md`（E2） | **+0.0512** | 整面板 rank（跨 73 期混合排名） |
| 正确的值 | **+0.0484 / +0.0496** | 期内 rank |

**三个数都不是"错误代码"报出来的**——都跑了，都没报错，都看起来合理。

### 1.2 根因：rank 在哪个维度上做

**`rank(pct=True)` 的作用范围取决于你传进去的 DataFrame 有多大。**

```python
# ❌ 整面板（73 期的所有行一起排名）
df["score"] = (df["gm"].rank(pct=True) - 1) * ...
# → 2010 年的股票在和 2026 年的股票比毛利率
# → 分数里混进了「时代漂移」

# ❌ 折内（一个折约 14 期的行一起排名）
fold = df[df.date.isin(fold_dates)]
fold["score"] = fold["gm"].rank(pct=True)
# → 折内不同期的股票互相比较

# ✅ 期内（每个 report 期内部排名）
df["score"] = df.groupby("accper_dt")["gm"].rank(pct=True)
# → 只在「同一期」内比较，符合截面因子的定义
```

### 1.3 为什么这个 bug 会虚高 IC

**我们的因子有明确的时间漂移**（D7/F8 实测）：

```
gm 中位数：2010 年 23.29% → 2017 年 27.48% → 2026 年 24.07%
```

**整面板 rank 的后果**：

```
2010 年的股票（毛利率普遍 23%）→ 排名偏低
2026 年的股票（毛利率普遍 24%）→ 排名偏高

而 2010-2013 的 IC 是 +0.11（高），2022-2024 是 −0.02（低）
→ 分数在时间上"偏向"了低 IC 的时期
→ 净效果：虚高 +0.0016
```

**实测验证**：

```
整面板 rank（错）: IC +0.0512
期内 rank（对）  : IC +0.0496
差异             : +0.0016
```

**0.0016 不大，但它是系统性偏差**——而且在样本更少、漂移更强的因子（如制造业组）上会更大。

## 二、唯一口径表（所有步骤必须遵守）

### 2.1 数据结构与对齐

| 项 | 唯一口径 | 代码 |
|---|---|---|
| **时间键** | 财报期 `accper_dt`（季度或年度，取决于因子披露频率） | `available_at` |
| **可用日** | 公告日（若已知）否则**法定披露截止日** | `available_at` |
| **标签对齐** | `merge_asof(direction="forward", tolerance=15天)` 从 `available_at` 起算 | — |
| **样本范围** | **部分覆盖**：任一因子非空即参与，分数按可用因子平均 | `composite_score` |
| **期内 rank** | **必须**：`groupby(accper_dt).rank(pct=True)` | `composite_score_panel` |

### 2.2 合成分数

| 项 | 唯一口径 |
|---|---|
| 权重 | **等权**（不按 IC 加权） |
| 分母 | **可用因子数**（不是固定因子总数） |
| 方向 | F0 的先验符号，若实测反号则以实测为准并记录 |
| 实现 | `metrics.composite_score_panel(df, factors, signs, "accper_dt")` |

**为什么等权**（M-S + unify_composite 实测）：

| 组 | 等权 | IC 加权 | 决定 |
|---|---|---|---|
| 全市场 | 0.0496 | 0.0495 | 等权（p=0） |
| 制造业 | 0.0592 | 0.0622 | 等权（权重估计误差 0.258 > 收益 0.003） |

### 2.3 IC 与显著性

| 项 | 唯一口径 | 为什么 |
|---|---|---|
| **IC 计算单位** | **每期截面一次** Spearman，再对期平均 | 股票-日混算会虚增显著性 |
| **样本数 n** | **有效报告期数**（70~74），不是股票-日 | 用行数会把 t 吹到 430 |
| **t 值** | **Newey-West HAC**，滞后 L = H = 60 | IC 序列有自相关 |
| **报告内容** | mean / std / ICIR / t_hac / CI / 中位 / IQR / 最差折 / 同号比例 | 单点均值无信息量 |
| **实现** | `metrics.hac_stats(ics)` | — |

### 2.4 增量显著性（两把尺）

| 尺 | 唯一口径 | 通过标准 |
|---|---|---|
| 尺一 | 两个 IC 各自的 95% CI 互不重叠 | 严格但在 n=70 下结构性不可通过 |
| **尺二** | **配对差**（同期内 IC_model − IC_baseline）+ HAC | **CI 排除零** |

**基线必须做方向调整**：

```
❌ 用 gm_vol 原始值（IC=−0.0311）当基线 → 配对差虚增到 0.0823
✅ 用 −gm_vol（IC=+0.0311）当基线 → 配对差 0.0185（正确）
```

### 2.5 long-only 分离（A 股专用）

| 量 | 公式 | 用途 |
|---|---|---|
| 多空价差 | Q10 − Q1 | 理论 alpha（纸面） |
| **多头超额** | **Q10 − 全样本均值** | **long-only 实际能拿到的** |
| 空头贡献 | 全样本均值 − Q1 | 拿不到的 |
| 空头占比 | 空头贡献 / 多空价差 | > 50% → 标注"long-only 不可用" |

### 2.6 其他

| 指标 | 唯一口径 |
|---|---|
| PSI | 用基准期分位点切 10 桶，`Σ(p_cur−p_base)ln(p_cur/p_base)`，下限 1e-4 |
| DSR | `SR_0 = √(V_SR)·[(1−γ)Φ⁻¹(1−1/N) + γΦ⁻¹(1−1/(Ne))]`，**V_SR = 1/(T−1) 不可漏** |
| 隐含换手 | `(252/interval) × (interval/H)`，年成本 = 年换手 × 2 × 单边 bp |
| 过拟合度 | `(IC_train − IC_test)/IC_train`，< 0.3 正常 / 0.3~0.6 轻度 / > 0.6 严重 |

## 三、历史不一致的完整取证

### 3.1 三个数字的来源

| 数字 | 出处 | 算法 | 判定 |
|---|---|---|---|
| **0.0402** | `model_choice.md`（M-S） | 折内 rank（5 折，每折约 14 期混排） | ❌ superseded |
| **0.0512** | `signal_eval.md`（E2）、`model_significance.md`（E3 v1） | 整面板 rank（73 期混排） | ❌ superseded |
| **0.0496** | 完全覆盖 + 期内 rank | 正确 | ✅ **当前口径** |
| **0.0484** | 部分覆盖 + 期内 rank | 正确（样本更大） | ✅ **正式报告用这个** |

### 3.2 差异分解实测

用四种组合分离两个因素（`metric_forensics.py`）：

| 变体 | IC | 相对 A 的差 |
|---|---|---|
| A 固定分母 + 完全覆盖（含期内 rank） | +0.0496 | — |
| B 固定分母 + 部分覆盖 | +0.0496 | −0.0001（样本范围几乎无影响） |
| C 可用数分母 + 完全覆盖 | +0.0496 | +0.0000（分母几乎无影响） |
| D 可用数分母 + 部分覆盖 | +0.0484 | −0.0012 |

**结论**：

```
① 分母（固定 vs 可用数）影响 ≈ 0
② 样本范围（完全 vs 部分覆盖）影响 −0.0012
③ 真正的大头是「rank 在哪个维度做」：
   整面板 rank → 0.0512（虚高 +0.0016）
   期内 rank   → 0.0496（正确）
```

**注意：折内 rank 与全样本 rank 的差异在 forensics 里测出为 0.0000** —— 因为我在那个脚本里两种都是「期内 rank」，只是切片方式不同。M-S 的 0.0402 另有原因（见下）。

### 3.3 M-S 的 0.0402 为什么与 0.0496 差这么多

**M-S 的 `cv_compare` 实现**：

```python
eq = sum(te[f].rank(pct=True) * signs[f] for f in factors) / len(factors)
```

**三个问题叠加**：

```
① `te` 是「测试折」的全部行（约 14 期）→ rank 跨期
② 固定除以 len(factors) = 3
③ 只在测试折上算（每折约 1/5 的期），但 IC 是对 5 折平均
```

**其中 ① 影响最大**：折内跨期 rank 让分数混入折内的时代漂移。

**结论**：M-S 的 0.0402 **不能与 0.0496 比较**，它是另一个东西。

**M-S 的结论（等权 > Ridge > GBDT）不受影响**——因为三者在同一个错误口径下比较，相对关系仍然成立。但**绝对数值应替换为 0.0496**。

## 七、一个方法论收获

**这件事的价值不在于修了一个 bug，而在于暴露了一类错误**：

```
这一类错误的特点：
  · 不报错（程序正常跑完）
  · 不荒谬（0.0402 / 0.0512 / 0.0496 都在合理范围）
  · 只在交叉核对时才暴露

常见的几种「口径漂移」：
  ① rank 在哪个维度做（本期 vs 跨期 vs 全样本）
  ② 分母是固定值还是可用数
  ③ 样本是完全覆盖还是部分覆盖
  ④ 分位数是用当期还是基准期算
  ⑤ 平均是先算各期再平均，还是先池化再算
```

**面试可以这么讲**：

> “我在 E3 阶段发现同一个组合在三个文档里有三个不同的 IC：0.0402、0.0512、0.0496。排查后发现是 `rank` 的作用域不同——有的在整面板上排名（73 期混排），有的在折内排名。我做了四变体分解实验，分离出三个因素各自的影响，最后建了一张指标口径登记表，把所有指标的算法固定下来，后面所有步骤都引用它。这件事让我意识到，**研究里最难发现的不是算法错误，而是口径漂移**——它不报错、数字也不荒谬，只在交叉核对时才暴露。”
