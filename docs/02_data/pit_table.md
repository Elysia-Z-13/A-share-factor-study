> 本文件是"代码里怎么防前视"的可执行规格。

## 一、四术语对齐

| 术语 | 定义 | 本项目例子 |
|---|---|---|
| **报告期**<br>`end_date` | 数据所属的业务期间 | 2024-12-31 |
| **公告日**<br>`ann_date` | 数据第一次对外披露的日期 | 2025-04-25 |
| **生效日**<br>`effective` | 制度/分类开始作用的日期 | 行业分类 `in_date` |
| **可用日**<br>`available_at` | **你能合法使用它的最早时刻** | 2025-04-25 收盘后 |

**关键等式**：

```
可用日 ≥ 公告日 ≥ 报告期
```

对财报来说，三者可能差 1~4 个月。**用错任何一个都是前视。**

## 二、每字段的 join 谓词（核心）

### 2.1 谓词类型总览

| 类型 | 谓词形式 | 适用字段 |
|---|---|---|
| **T0** 当日可得 | `field.date = T` | 行情类 |
| **T1** 盘前可得 | `field.date = T`（但用 T−1 收盘计算） | 涨跌停价、ST 标记 |
| **T2** 公告后可用 | `field.ann_date <= T`，取 `end_date` 最大 | 财报类 |
| **T3** 区间生效 | `in_date <= T < out_date` | 行业、上市退市 |
| **T4** 需滞后一期 | `field.date <= T - 1` | 执行价格（T+1 开盘） |

### 2.2 完整字段表

| 字段 | 类型 | join 谓词（可直接翻译成 SQL） | 说明 |
|---|---|---|---|
| `code, date` | — | 主键，无时点 | — |
| `open` | T0 | `date = T` | T 日 09:30 后可知 |
| `high, low` | T0 | `date = T` | T 日 15:00 后可知 |
| `close` | T0 | `date = T` | T 日 15:00 后可知 |
| `close_adj` | T0 | `date = T` | 后复权，T 日 15:00 后可知 |
| `open_adj` | T0 | `date = T` | 派生：`open × (close_adj/close)` |
| `volume, amount` | T0 | `date = T` | T 日 15:00 后可知 |
| `float_mv` | T0 | `date = T` | T 日 15:00 后可知 |
| `limit_up, limit_down` | **T1** | `date = T`，但**用 T−1 的 close 计算** | 交易所 T 日 09:15 公布 |
| `trade_status` | **T1** | `date = T` | ST/停牌状态 T 日盘前可知 |
| `st_flag` | T1 | `trade_status ∈ {2,3,6}` | 同上 |
| `suspended` | T0 | 该日无行情记录 | T 日收盘后可知 |
| `end_date` | — | **不可用于决策**，仅作匹配键 | 报告期本身不是可用日 |
| `ann_date` | T2 | `ann_date <= T` | **PIT 唯一合法键** |
| `if_correct` | T2 | 同一 `(code, end_date)` 取 `ann_date` 最大者 | 更正版覆盖原版 |
| `typrep` | T2 | `typrep = 'A'` | 只用合并报表 |
| `revenue, cogs, gm` | **T2** | `ann_date <= T`，`ORDER BY end_date DESC LIMIT 1` | 毛利率及其派生 |
| `dgm_q` | **T2** | 同上，再按 `end_date` 差一期 | 单季毛利率变化 |
| `fa_net, cip, total_asset` | **T2** | `ann_date <= T`，取最新期 | 固定资产/在建工程 |
| `transfer_from_cip` | **T2** | `ann_date <= T`（Fa02007） | 在建工程转入 |
| `dep_add` | **T2** | `ann_date <= T`（Fa02004） | 折旧计提 |
| `list_date` | **T3** | `date >= list_date` | 上市前已知（招股书） |
| `delist_date` | **T3** | `date <= delist_date` | 退市前有公告 |
| `industry_code` | **T3** | `in_date <= T AND (out_date IS NULL OR out_date > T)` | 历史归属 |
| `adj_factor` | T0 | `date = T` | **后复权**（见第四节） |

### 2.3 两条必须同时带的谓词（G-D2.5）

**所有跨源 join 必须同时满足两条**：

```sql
-- 谓词一：时点约束（不能用未来信息）
AND field.available_at <= T

-- 谓词二：区间约束（取生效中的那条）
AND field.effective <= T AND (field.end IS NULL OR T < field.end)
```

**缺任一条都是前视，而且不会报错。**

**反例**：

```sql
-- ❌ 只有时间对齐，没有时点约束
LEFT JOIN financials f ON f.code = d.code AND f.end_date = d.date
-- 财报一年只有 4 条，这个 join 几乎匹配不上
-- 但如果你改成 f.end_date <= d.date 取最大，就前视了

-- ✅ 正确
LEFT JOIN financials f
  ON f.code = d.code
 AND f.announce_date <= d.date        -- 谓词一
QUALIFY ROW_NUMBER() OVER (
  PARTITION BY d.code, d.date ORDER BY f.end_date DESC) = 1
```

## 三、六个前视来源逐个排查（G-D2.3）

| # | 前视来源 | 本项目检查 | 实测结论 |
|---|---|---|---|
| **1** | **用报告期当可用时点** | 对照实验一 | ❌ 会导致 IC 虚高 **1.78 倍** |
| **2** | **用当日收盘价当成交价** | 标签定义 | ❌ 改为 **T+1 开盘买入** |
| **3** | **用当前行业分类当历史行业** | 用 `in_date` 重建 | ✅ 已用区间表 |
| **4** | **用未来视角的 universe** | 对照实验二 | ⚠️ 剔退市使年化虚高 **+0.30%** |
| **5** | **用前复权（含未来分红）价** | 用后复权 `Adjprcwd` | ✅ 见第四节 |
| **6** | **用未来才知道的退市标记** | 用行情末行推导 `last_date` | ✅ 已处理 |

### 逐个说明

**① 报告期当可用时点**

```
❌ 2024-12-31 的报告期，2025-01-02 就用
✅ 2025-04-25 公告日后才能用
```

**② 用当日收盘价当成交价**

```
❌ label = close[t+H]/close[t] - 1
   T 日 15:00 才知道收盘价，无法在 15:00 前下单
✅ label = close_adj[t+H]/open_adj[t+1] - 1
```

**③ 当前行业分类当历史行业**

```
❌ 用今天申万分类回填 2015 年
   → 2015 年属于 A 行业的股票，
     今天被划到 B 行业，你就用 B 行业的数据分析它
✅ 用 index_member 的 in_date/out_date 重建当时的归属
```

**④ 未来视角的 universe**

```
❌ 只保留「今天还在交易」的股票
   → 提前剔除了后来退市的股票
   → 幸存者偏差
✅ 保留全部历史股票，只用「当时可交易」标记
```

**⑤ 前复权价含未来分红**

```
❌ 前复权：以今天为基准，t 日的因子会随「未来分红」变化
   → 同一个 t 日，2020 年看到的因子 ≠ 2026 年看到的因子
✅ 后复权：以首日为基准，t 日因子只反映 t 之前的分红
```

**⑥ 退市标记用未来信息**

```
❌ 用今天的退市名单
✅ 用行情末行推导 last_date（当时就能观察到"不再出现"）
```

## 四、复权因子的时点正确性（G-D2.6）

**本项目用的是 CSMAR `Adjprcwd`（后复权），符合"当时可见"要求。**

| 口径 | 因子定义 | 含未来信息？ | 可复现？ |
|---|---|---|---|
| 不复权 | — | 否 | ✅ |
| **后复权（本项目）** | 以首日为基准，乘以历史累计分红系数 | **否** ✅ | ✅ |
| 前复权 | 以最新日为基准，反向调整 | **是** ❌ | ❌ |

**为什么后复权安全**：

```
后复权因子 t 的值 = Π(1 + 分红调整系数)  for 所有 分红日 ≤ t
→ 只依赖 t 之前的信息
→ 2020 年算出来的因子，2026 年看还是同一个值
```

**为什么前复权危险**：

```
前复权因子 t 的值 = 后复权因子 t / 后复权因子 最新日
→ 分母随最新日的分红变化
→ 每次分红，全部历史都被改写
→ 不可复现，且隐含未来信息
```

**验证方法**：

```python
# 后复权因子应随时间单调不减（只在分红日跳升）
adj = close_adj / close
assert (adj.groupby(code).diff().fillna(0) >= -1e-6).all()
```

**实测**：5,970 只全部在分红日跳升，7 只有下降（并股/缩股个案）。

## 五、两个对照实验（G-D2.4）

### 实验一：财报时点泄漏的代价

**设计**：用同一个因子（毛利率 `gm`），只改时点规则，比较 rank IC。

| 组 | 规则 | 期数 | IC 均值 | t 值 | 财报覆盖率 |
|---|---|---|---|---|---|
| **A 正确** | `ann_date <= T` | 168 | **+0.00774** | +1.07 | **61.5%** |
| **B 错误** | `end_date <= T` | 183 | **+0.01382** | +1.73 | 98.0% |

**结论**：

```
错用时点 → IC 虚高 1.78 倍（0.00774 → 0.01382）
         → t 值从 1.07 提到 1.73
         → 一个本来不显著的因子，看起来"接近显著"
```

**这个实验的价值**：

> 如果有人问"PIT 处理真的那么重要吗"，答案是：**会让 IC 虚高 78%**。

**同时暴露一个副作用**：

```
正确 PIT 的覆盖率只有 61.5%，错误方式有 98.0%
原因：CSMAR 的 DeclareDate 在早期年份大量缺失
     丢弃缺失公告日的记录 → 损失 38.5% 的样本
```

**处理决策**：

```
不用「报告期 + 90 天」兜底（会引入前视）
接受 61.5% 的覆盖率
若覆盖率过低影响统计功效，则把样本起点从 2010 推迟到 2015（公告日完整）
```

### 实验二：幸存者偏差的代价

**设计**：等权组合，只改股票池。

| 组 | 股票池 | 股票数 | 每期收益 | 年化 |
|---|---|---|---|---|
| **A 含退市** | 全历史所有股票 | 5,970 | +3.089% | **+12.98%** |
| **B 不含退市** | 只留最后一天仍在交易的 | 5,655 | +3.160% | **+13.27%** |

**结论**：

```
剔除退市股 → 年化虚高 +0.30%
（12.98% → 13.27%）
```

**为什么只有 0.30% 而不是文献里说的 2~5%**

```
我们的退市股只有 315 只（5.3%）
A 股的退市率本来就低（相比美股）
且这些退市股多是 ST 后长期阴跌，不是突然归零
→ 影响比美股小
```

**但 0.30% 仍然不可忽略**：

```
如果年化超额只有 2%，0.30% 就是 15% 的相对误差
```
