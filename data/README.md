# 数据目录（CSMAR 原始数据不入库）

把从 CSMAR 导出的 CSV 放在本目录下，文件名与字段要求如下。

## 必需文件

| 文件名 | 来源 | 关键字段 |
|---|---|---|
| `prices_YYYY.csv` | 日频行情（2010~2026） | `code, date, open, close, high, low, volume, amount` |
| `adjfactor_YYYY.csv` | 复权因子 | `code, date, adjfactor` |
| `universe_YYYY.csv` | 可交易标记 | `code, date, tradable, hit_limit_up` |
| `FS_Comins.csv` | 利润表 | `Stkcd, Accper, DeclareDate, B001100000, B001200000` |
| `FS_Combas.csv` | 资产负债表 | `Stkcd, Accper, DeclareDate, A001212000, A001123000` |
| `FN_Fn020.csv` | 固定资产附注 | `Stkcd, Accper, Fn02003, Fn02004, Fn02007` |

## 字段说明

- `code` / `Stkcd`：6 位股票代码（需补零）
- `date` / `Accper`：日期，`YYYY-MM-DD`
- `DeclareDate`：实际公告日。**实测填充率仅 5~8%**，缺失时由代码用法定披露截止日代理
- `B001100000`：营业收入；`B001200000`：营业成本
- `A001212000`：固定资产原值；`A001123000`：在建工程
- `Fn02003`：固定资产原值（期初）；`Fn02004`：本期折旧增加；`Fn02007`：在建工程转入

## 重要提示

### 1. 公告日缺失是常态，不是异常

CSMAR 的 `DeclareDate` 填充率：

| 表 | 填充率 |
|---|---|
| `FS_Comins`（利润表） | 5.0% |
| `FS_Combas`（资产负债表） | 7.7% |
| `FN_Fn020`（固定资产附注） | **无此列** |

本项目采用**法定披露截止日**代理：

```
年报（12-31）  → 次年 4月30日
一季报（3-31） → 当年 4月30日
半年报（6-30） → 当年 8月31日
三季报（9-30） → 当年 10月31日
```

**这个代理是保守的（永远不提前），但会让信号可用时间推迟最长 4 个月。**

### 2. 固定资产附注只有年报/半年报

`FN_Fn020` 的报告月分布实测：

| 月份 | 行数 |
|---|---|
| 3 月 | **0** |
| 6 月 | 3,929 |
| 9 月 | **0** |
| 12 月 | 59,547 |

→ **一季报与三季报不披露固定资产明细**
→ 该表实质是「一年一期」
→ 与 H=60 的标签存在 **4 倍时限错配**
→ 这也是 `transfer_intensity` / `dep_rate` 在 E1 被 STOP 的根本原因
